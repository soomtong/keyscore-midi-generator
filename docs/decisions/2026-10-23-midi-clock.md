# MIDI Clock 송신 (2026-10-23)

## 배경
가상악기의 아르페지에이터, 템포 싱크 LFO, 딜레이는 앱의 템포를 알 수 없어 사용자가 BPM 을 손으로 맞춰야 했다.
재생 중 송신은 노트와 CC(64, 123)뿐이었고, 템포는 MIDI 파일 내보내기(FF 51)에만 들어갔다.

## 결정

### MIDI 1.0 Clock 과 Start/Stop/Continue/SPP, 기본은 끔
- 수신 측 지원이 가장 넓은 방식이다. Ableton Link 는 지원 앱끼리만 되고 SDK 가 필요하며,
  MIDI 2.0 Flex Data(Set Tempo)는 아직 받는 쪽이 거의 없다.
- Clock 을 받으면 자기 트랜스포트가 움직이는 수신기(DAW 등)가 있으므로 기본은 끈다.
  설정 카드와 재생 메뉴에서 켜고, 상태는 UserDefaults(midi.sendClock)에 남긴다. 상단 디스플레이 메트로놈 아이콘이 켜짐을 보여 준다.
- 가상 소스는 "KeyScore" 하나 그대로다. Clock 용 소스를 따로 두지 않는다 (대부분의 수신기는 노트와 같은 입력에서 Clock 을 받는다).

### 펄스는 메시지 목록에 넣지 않고 계산한다
- k 번째 펄스 시각은 k × 60 / bpm / 24. MidiPlayer 의 one-shot 타이머가 다음 메시지·다음 펄스·진행 보고 중 빠른 쪽에 맞춰 깨어난다.
  120 BPM 이면 초당 48회로 진행 보고(20회)보다 많지만 폴링이 아니므로 부담이 작다.
- 목록에 넣으면 최대 곡(12분, 200 BPM)에 5만 개가 더해지고, 재생 중 켜고 끌 때 목록을 다시 만들어야 한다.
- 같은 시각이면 Clock 이 노트보다 먼저 나간다. 펄스 시각(k × step)과 노트 시각(박 × spb)은 몇 ulp 어긋날 수 있어 1 µs 안은 같은 시각으로 본다.
  같은 tick 의 메시지는 기존대로 MIDIEventList 하나에 묶인다.
- UMP 로는 System Real Time/Common(0xF1...0xFF)을 type 1 로 보낸다 (Channel Voice 는 type 2). enqueue 가 상태 바이트로 고른다.
  SysEx(0xF0, 0xF7)는 여러 워드의 type 3 이라 enqueue 로 보내지 않는다 (assert).
- 한 바퀴의 펄스 수는 곡 끝 직전 펄스까지(clockCount).
- Clock 을 보내는 반복 재생은 바퀴 길이를 펄스 격자로 올린다 (clockCount × step). Legato 여유처럼 곡 길이가 1/24 박 단위가 아니면
  바퀴 경계의 펄스 간격이 짧아져 펄스 주기로 템포를 재는 수신기가 바퀴마다 흔들리기 때문이다. 늘어나는 것은 한 펄스 미만이다.
- 반복 재생은 바퀴 끝에서 남은 메시지를 기다리지 않고 바로 되감는다. 곡 끝을 넘어 울리던 음은 되감을 때 Note Off 로 끊고,
  바퀴 끝 너머의 Note On 은 보내지 않는다. 기다리면 그동안 Clock 이 끊긴다. 한 번 재생은 전처럼 마지막 메시지까지 보낸 뒤 끝낸다.

### 트랜스포트
- 재생 시작: Start(0xFA) 뒤 t = 0 의 첫 펄스가 곡의 첫 박. MIDI 1.0 권고대로 Start 와 첫 펄스 사이에 1 ms(startLead)를 둔다.
- 정지(사용자 정지·곡 끝·다른 재생으로 교체·앱 종료): Stop(0xFC) 을 Note Off 보다 먼저 보내 수신 측 시퀀서를 먼저 세운다.
  ⌘Q 는 willTerminate 알림에서 송신 큐를 동기로 비우고(stopNow) 보내며, MidiPlayer 가 해제될 때도 같은 정리를 한다.
- Stop 은 Start/Continue 를 보낸 뒤에만 보낸다 (running). 재생 중에 켰지만 이번 바퀴를 건너뛰었다면 곡 끝에 Stop 을 보내지 않아
  다른 마스터가 돌리던 수신기를 세우지 않는다.
- 반복 재생이 처음으로 돌아갈 때 Start 를 다시 보낸다. 곡이 처음으로 돌아가므로 수신 측도 처음부터 세는 것이 맞고,
  스케일 듣기(7.5박)처럼 마디 단위가 아닌 곡도 마디 위치가 어긋나지 않는다. Start 는 마지막 펄스 뒤, 바퀴 끝 1 ms 앞에 미리 보낸다.
- 재생 중에 켜면 1 ms 이상 남은 다음 16분음표 자리를 Song Position Pointer(0xF2)로 알리고 Continue(0xFB) 뒤 그 자리부터 펄스를 보낸다.
  SPP 는 수신 측이 멈춰 있을 때 보내야 하는데, Clock 을 받기 전이므로 멈춰 있다. 이번 바퀴에 남은 펄스가 없거나 그 자리가 SPP 범위
  (16383 16분음표)를 넘으면 다음 바퀴의 Start 를 기다린다.
- 재생 중에 끄면 바로 Stop 을 보내고 펄스를 멈춘다.

## 생략한 것
- 멈춰 있을 때의 상시 Clock: 일부 마스터는 정지 중에도 Clock 을 보내 수신 측이 템포를 미리 잡게 한다.
  KeyScore 는 짧은 청취를 자주 다시 트는 앱이라, 정지 중 송신이 수신 측 트랜스포트를 깨우는 부작용이 더 크다고 봤다.
  템포 추정에 몇 펄스가 필요한 수신기는 첫 박이 조금 흔들릴 수 있다. 필요해지면 옵션으로 더한다.
- 재생 중 템포 변경: BPM 을 바꾸면 지금처럼 곡을 다시 튼다 (Stop → Start). 펄스 간격만 부드럽게 바꾸려면 플레이어가
  재생 중 템포 변경을 받아야 하므로 따로 다룬다.
- MTC(MIDI Time Code): 영상 동기용이라 대상이 아니다.

## 검증
- MidiClockTests: 기본 꺼짐, Start → 박당 24 펄스 → Stop 순서와 펄스 간격 오차, 박마다 Note On 이 24 펄스째와 같은 시각,
  반복 바퀴마다 Start 와 같은 펄스 수, 재생 중 켜기(SPP + Continue, Start 없음)와 끄기(Stop 한 번),
  Start 뒤 첫 펄스까지 1 ms, 격자에 맞지 않는 곡 길이에서도 바퀴를 거쳐 펄스 격자 유지, 곡 끝을 넘는 음이 있어도 Clock 공백 없음,
  건너뛴 바퀴 뒤 짝 없는 Stop 없음.
- 수신 시각 기반 테스트는 부하가 크면 지터(10~20 ms)로 간헐 실패할 수 있어, 새 테스트는 중앙값과 큰 공백으로 판정한다.
